# cleanTMLE 0.4.0: design spec

Date: 2026-10-05. Status: draft for review.

## 1. Purpose and scope

cleanTMLE 0.3.0 exports 65 functions, carries at least five TMLE implementations, and has two validity problems at the center of its main claim. The candidate that the stress test selects is not the candidate that stage 4 estimates: `.tmle_delegate_args()` never passes the selected truncation, so `tmle::tmle` falls back to its default bound of `5/sqrt(n)/log(n)`, and it uses the outcome library for the propensity model as well. Blinding is a convention, not a barrier: the outcome sits in `lock$outcome_store`, an unhashed flag gates estimation, and `unmask_outcome()` accepts a different lock.

0.4.0 rebuilds the package inside the existing repository (breaking changes allowed) around one claim the estimability paper needs: an outcome-free support map that says, for each declared estimand, whether the design can deliver it, paired with an estimand ladder that is decided before any outcome is seen. Success means:

- 12 exports and one example dataset, about 2,500 lines of R;
- the simulation and the final analysis call the same fitter with the same candidate, enforced by a test;
- no design-stage object ever holds the primary outcome, enforced by a test;
- any change to the plan, design data or decision after the fact is detectable from the hashes.

Out of scope here, each with its own later design cycle, in this order: the vignette rewrite, the backwards redesign of the paper's simulation, and the paper itself.

## 2. Decisions

| Topic | Decision |
|---|---|
| Build | Rebuild in the cleanTMLE repository; history and URL preserved. Tag `v0.3.0` first. |
| Name | Keep cleanTMLE. TMLE stays the default and the only stress-tested method. |
| Time-to-event | Stage-4 backend only, through `concrete`. The simulation treats risk by the target time as binary. ATT and ATO are rejected for time-to-event outcomes. |
| Outcome surfaces | Outcome-free by default: a declared family, never fitted to the outcome. An optional steward-supplied `q0` replaces the prognostic index. The 0.3.0 hybrid mode is removed. |
| Estimators | TMLE (default), plus weighting (WeightIt) and matching (MatchIt) as comparators. |
| Features kept | Negative-control ladder; Quarto dossier. |
| Features dropped | Data-quality threat families and the GO/FLAG/STOP stress verdict; multiple selection rules (one rule plus a user hook remains); process-indicator collider check (moves to the Rescue.Co scripts). |
| Fitting scheme | Cross-fitting with K declared in the plan (default 5, inner V = 5); K = 1 allowed. The simulation and stage 4 always use the same K. |
| Missing binary outcomes | Complete case; the count dropped goes to the design log. The 0.3.0 IPCW option for binary outcomes is removed. |

## 3. Public surface

```r
plan <- analysis_plan(
  outcome     = "death_30d",       # or c(time = "t", event = "status"), target_time = 365
  estimands   = c("ATE", "trimmed_ATE", "ATT", "ATO"),   # ordered ladder
  ps_library  = "default",         # propensity library, used by every candidate
  candidates  = list(library = list(glm = "SL.glm", sl = "default"),
                     truncation = c(0.01, 0.05)),
  tolerance   = list(bias = 0.02, coverage = 0.90),
  surfaces    = list(baseline_risk = 0.10, log_or = 0.5, heterogeneity = 0.5,
                     forms = c("linear", "nonlinear")),
  trim_band   = c(0.05, 0.95),
  negative_controls = list(nc_visit = "health_seeking_behavior"),
  nc_criteria       = list(null_band = c(-0.02, 0.02), min_per_domain = 1),
  restrictions      = list(no_transfer = ~ !transfer),
  K = 5, reps = 200, seed = 20261005)

lock    <- create_analysis_lock(design_data, treatment = "A", covariates = W,
                                plan = plan, id = "id")
design  <- assess_design(lock)
sim     <- simulate_design(lock, design)
nc      <- negative_control_ladder(lock, design)
dossier <- design_report(lock, design, sim, nc, file = "dossier.html")
ub      <- unblind(lock, dossier, outcomes = outcome_data,
                   approved_by = "Review team")
fit     <- estimate_effect(ub, method = "tmle")   # or "weighting", "matching"
export_design_log(ub, fit, file = "design_log.json")
```

Exports (12): `analysis_plan`, `create_analysis_lock`, `assess_design`, `simulate_design`, `negative_control_ladder`, `design_report`, `unblind`, `estimate_effect`, `export_design_log`, `save_lock`, `load_lock`, `verify_lock`. S3 methods: `print`, `summary`, `plot`, `as.data.frame`, `tidy`. One example dataset, shipped as separate design and outcome data frames, replaces `sim_func1()`.

A library is a character vector of learner names or the string `"default"`, which expands to the default library of Section 4; the expansion is stored in the plan, so the hash covers it. `tolerance$bias` is absolute bias on the risk-difference scale. `analysis_plan()` validates the plan: estimands from {ATE, trimmed_ATE, ATT, ATO}; ATT and ATO rejected for a time-to-event outcome; `trim_band` required when `trimmed_ATE` is declared; `select` optional (a function of the metrics table, replacing the default rule); `hazards` required for a time-to-event outcome (the hazard-model specification passed to `concrete`). Every declaration lives in the plan; nothing is declared after the lock is created.

## 4. The fitter: `fit_candidate()`

One internal function serves the simulation (on W, A\*, Y\*) and stage 4 (on the real data, with the candidate the dossier recorded). It has two layers.

**`fit_nuisance(W, A, Y, ps_library, q_library, folds)`** returns cross-fitted g(W), Q(1,W) and Q(0,W), and the cross-validated risk of every learner setting.

- K outer folds; within each training set, a Super Learner with V = 5 inner folds. With K = 1, one Super Learner fit on all rows with V = 5, and predictions from that fit.
- The propensity library is `ps_library` for every candidate. Candidates vary only the outcome library and the truncation.
- Folds are seeded from the plan; every setting uses the same folds.

**`target(nuisance, estimand, truncation)`** is cheap, so one nuisance fit serves every estimand and truncation level.

| Estimand | Targeting |
|---|---|
| ATE, ATT | `tmle::tmle(Y, A, W, Q = cbind(Q0W, Q1W), g1W = g, gbound = c(t, 1 - t), family = "binomial")`. Verified: supplied nuisances are accepted and the bound reaches both the ATE and the ATT. |
| Trimmed ATE | The same call on rows whose cross-fitted g lies inside `trim_band`, with the full-sample nuisance fits. No propensity refit. |
| ATO | Internal TMLE. Fluctuate logit Q along the covariate H = A(1 − g) − (1 − A)g; then ψ = Σ h(Q₁\* − Q₀\*) / Σ h with h = g(1 − g); SE from the influence function. Truncation has no effect, so ATO candidates collapse over truncation. |

Every estimate goes through the implausibility guard carried over from 0.3.0.

**Learners.** The package ships its own xgboost learner, because `SL.xgboost` leaves `tree_method` unset (exact split search; in a probe at n = 2000 on a busy machine, one 500-tree fit took 90 s through `SL.xgboost` and under 1 s with `hist`) and fits a fixed number of trees. The learner uses `tree_method = "hist"`, `nthread = 1`, `min_child_weight = 0`, depths 1 to 5, learning rates 0.1 and 0.3, and the best round within a 500-tree cap chosen on the inner folds; each depth and learning rate enters the library as its own setting. The default library is one learner type per family: elastic net (`glmnet`), MARS (`earth`, degree 2), that xgboost grid, and a small neural net (`nnet`). Every fit stores per-setting and per-round risks; the edge check reads them and reports any tuned hyperparameter whose best value sits on a grid edge (depth 1 is a hard limit and exempt).

## 5. Design stage

**`assess_design(lock)`** cross-fits g with `ps_library`, grades overlap, reports per-estimand weights and effective sample size, checks balance with cobalt, and reports the edge check. It reads only the design data.

**`simulate_design(lock, design)`** runs one plasmode loop that answers which estimands the data can deliver and which candidate to use for each. One repetition, for each surface s:

1. Resample the rows of W with replacement; draw A\* ~ Bernoulli(ĝ(W)), with ĝ from `design`.
2. Draw Y\* ~ Bernoulli(Q_s(A\*, W)).
3. Fit the nuisances once per repetition for g and once per surface and outcome library for Q, then target every (estimand, truncation) pair.
4. Record bias, interval coverage and squared error against the true values.

The true values are computed exactly from Q_s and ĝ over the design sample's W, the finite population being resampled, so they are fixed across repetitions: ATE is the mean of Q_s(1,W) − Q_s(0,W); ATT weights it by ĝ; ATO by ĝ(1 − ĝ); trimmed ATE averages over rows with ĝ inside `trim_band`.

The surface family is Q_s(a,W) = expit(β₀ + γ·m(W) + a·(τ + δ·h(ĝ(W)))). m(W) is a prognostic index, a fixed mix of logit ĝ(W) and a seeded random direction in the standardized covariates, either linear or nonlinear (squares and one interaction). τ is `log_or`; δ is `heterogeneity`, which makes the effect vary with the propensity score, the variation that separates the ATE, ATT and ATO; β₀ is calibrated to `baseline_risk`. The default grid is {linear, nonlinear} × {δ = 0, δ = heterogeneity}, four surfaces. Users can add surfaces as `function(a, W)` returning risks, or supply `q0`, which replaces m(W).

Reading the results:

- **Feasible:** at least one candidate meets the bias and coverage tolerances on every surface.
- **Selected:** among candidates for a feasible estimand, the smallest worst-surface RMSE, unless the plan supplies `select`.
- **Borderline:** a metric within 2 Monte Carlo SEs of its tolerance. Every metric carries its Monte Carlo SE.
- **Failures:** a fit that errors is recorded as failed; a candidate with more than 5% failed fits on any surface does not count toward feasibility.
- **Runtime:** a runtime estimate prints after the first repetition. Repetitions run in parallel through `future.apply` when it is installed and a plan is set.
- **Scope:** the dossier states that feasibility is certified only over the declared family of surfaces.

For a time-to-event outcome, the loop scores risk by `target_time` as a binary outcome; it checks support and selects the truncation only. The dossier states that the hazard models were not stress-tested.

**`negative_control_ladder(lock, design)`** runs `fit_candidate()` (ATE, main-terms GLM candidate, the design's folds) for each negative-control outcome on each rung of `restrictions`, starting with the full cohort, and grades the result against `nc_criteria`: per rung and domain, pass, fail or insufficient; the rung verdict is STOP when any domain fails, FLAG when any is insufficient, otherwise GO.

## 6. Integrity: lock, dossier, unblinding

**Lock.** `create_analysis_lock()` raises an error if `design_data` contains any of the plan's outcome columns; negative-control outcomes are allowed. It stores the design data, plan, seed and package version. `lock_hash` is SHA-256 over: the plan (function-valued entries deparsed to text), a content digest of every design-data column, the treatment and covariate names, the seed, K, and the package version. Nothing is written back into the lock after creation. `verify_lock()` recomputes the hash; `save_lock()` and `load_lock()` verify on the way out and in.

**Stamps.** `assess_design()`, `simulate_design()` and `negative_control_ladder()` return objects stamped with `lock_hash` and their own content hash.

**Dossier.** `design_report()` checks every stamp against the lock, then walks the ladder: the primary is the first estimand in the declared order that is feasible and not borderline, and each feasible estimand gets its selected candidate. It attaches the negative-control verdict, strips individual-level vectors, and computes `dossier_hash` over the lock hash, the decision and the component hashes. `file =` renders a Quarto HTML or Word file.

**Unblinding.** `unblind(lock, dossier, outcomes, approved_by, override = NULL)`:

- recomputes the lock and dossier hashes and checks that the dossier belongs to this lock;
- requires `outcomes` to carry the `id` column and the plan's outcome columns; ids not in the design are dropped and logged;
- refuses when no estimand is feasible or the negative-control verdict is STOP, unless `override` gives a written reason, which is recorded;
- returns an `unblinded_lock` holding the lock, dossier, outcomes and approval record (approver, time). The original lock is unchanged.

**Estimation.** `estimate_effect(ub, method = "tmle")` reads the estimand and candidate from the dossier. An explicit `estimand =` is allowed and labeled, in the result and the log, as not the prespecified primary.

**Design log.** `export_design_log()` assembles JSON at export time from the stamps on the objects it receives: plan, hashes, design summaries, decision, approval, overrides, estimates. There is no mutable log.

**Guarantee, stated plainly.** The outcome never enters the lock or a design object (structural, tested), and any later change to the plan, design data or decision is detectable through the hashes. Nothing in R prevents an analyst from reading their own outcome file, so the package and the paper describe the design as tamper-evident, not tamper-proof.

## 7. Estimation backends

All methods return one class, `cr_estimate`: estimand, method, candidate, estimate, SE, CI, n, the size of the target population, the arm risks, and the implausibility guard. `summary()` adds an E-value from `EValue::evalues.RR` on the ratio of the arm risks; with the threat families dropped, this is where the unmeasured-confounding tipping point lives.

| Method | Estimands | Implementation |
|---|---|---|
| `"tmle"` (default) | all four | `fit_candidate()` with the dossier's candidate |
| `"weighting"` | ATE, ATT, ATO, trimmed ATE | `WeightIt::weightit()` (trimmed ATE on the band subset), then `lm_weightit(Y ~ A)` for a risk difference with an M-estimation SE |
| `"matching"` | ATT only | `MatchIt::matchit()` nearest neighbour, caliper 0.2 SD of the logit, then a regression with cluster-robust SEs |
| time-to-event (dispatched by the plan) | ATE, trimmed ATE | `concrete::formatArguments()` (treatment model `ps_library`, `MinNuisance` = the candidate's truncation, hazards from the plan), `doConcrete()`, `getOutput(Estimand = "Risk")` at `target_time` |

The comparators are not simulated; the dossier and the result label them as not stress-tested.

## 9. Tests

Written before the code they cover.

1. **Lock:** outcome columns refused; changing any plan field or design column changes the hash; save and load round-trip; `verify_lock()` detects tampering.
2. **Blinding contract:** a recursive walk finds no outcome column or vector in any design object or dossier; `simulate_design()` runs on design data with no outcome columns.
3. **Fitter:** the handoff test (`estimate_effect()` passes exactly the dossier's library, truncation and fold seed to `fit_candidate()`); truncation changes the ATE and ATT; the ATO TMLE agrees with the augmented ATO estimator and recovers a known truth; the exact true values match a large Monte Carlo draw.
4. **Simulation:** good overlap gives a feasible ATE; severe positivity gives an infeasible ATE and a feasible ATO; the borderline and failure rules; K is respected.
5. **Dossier and unblinding:** a dossier from another lock is rejected; an edited dossier is rejected; STOP blocks without an override; the override is recorded.
6. **Backends:** weighting matches a direct WeightIt call; matching rejects every estimand but the ATT; a `concrete` smoke test with `skip_if_not_installed()`.
7. **Edge check:** a deliberately narrow grid is flagged.
