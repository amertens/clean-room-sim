# cleanTMLE 0.4.0: design spec

Date: 2026-10-05. Status: draft for review.

## 1. Purpose and scope

cleanTMLE 0.3.0 exports 65 functions, carries at least five TMLE implementations, and has two validity problems at the center of its main claim. The candidate that the stress test selects is not the candidate that stage 4 estimates: `.tmle_delegate_args()` never passes the selected truncation, so `tmle::tmle` falls back to its default bound of `5/sqrt(n)/log(n)`, and it uses the outcome library for the propensity model as well. Blinding is a convention, not a barrier: the outcome sits in `lock$outcome_store`, an unhashed flag gates estimation, and `unmask_outcome()` accepts a different lock.

0.4.0 rebuilds the package inside the existing repository (breaking changes allowed) around one claim the estimability paper needs: an outcome-free support map that says, for each declared estimand, whether the design can deliver it, paired with an estimand ladder that is decided before any outcome is seen. Success means:

- 12 exports and one example dataset, about 2,500 lines of R;
- the simulation and the final analysis call the same fitter with the same candidate, enforced by a test;
- no design-stage object ever holds the primary outcome, enforced by a test;
- any change to the plan, design data or decision after the fact is detectable from the hashes.

Out of scope here, each with its own later design cycle, in this order: the vignette rewrite, the backwards redesign of the paper's simulation, and the paper itself.

## 2. Decisions

| Topic | Decision |
|---|---|
| Build | Rebuild in the cleanTMLE repository; history and URL preserved. Tag `v0.3.0` first. |
| Name | Keep cleanTMLE. TMLE stays the default and the only stress-tested method. |
| Time-to-event | Stage-4 backend only, through `concrete`. The simulation treats risk by the target time as binary. ATT and ATO are rejected for time-to-event outcomes. |
| Outcome surfaces | Outcome-free by default: a declared family, never fitted to the outcome. An optional steward-supplied `q0` replaces the prognostic index. The 0.3.0 hybrid mode is removed. |
| Estimators | TMLE (default), plus weighting (WeightIt) and matching (MatchIt) as comparators. |
| Features kept | Negative-control ladder; Quarto dossier. |
| Features dropped | Data-quality threat families and the GO/FLAG/STOP stress verdict; multiple selection rules (one rule plus a user hook remains); process-indicator collider check (moves to the Rescue.Co scripts). |
| Fitting scheme | Cross-fitting with K declared in the plan (default 5, inner V = 5); K = 1 allowed. The simulation and stage 4 always use the same K. |
| Missing binary outcomes | Complete case; the count dropped goes to the design log. The 0.3.0 IPCW option for binary outcomes is removed. |

## 3. Public surface

```r
plan <- analysis_plan(
  outcome     = "death_30d",       # or c(time = "t", event = "status"), target_time = 365
  estimands   = c("ATE", "trimmed_ATE", "ATT", "ATO"),   # ordered ladder
  ps_library  = "default",         # propensity library, used by every candidate
  candidates  = list(library = list(glm = "SL.glm", sl = "default"),
                     truncation = c(0.01, 0.05)),
  tolerance   = list(bias = 0.02, coverage = 0.90),
  surfaces    = list(baseline_risk = 0.10, log_or = 0.5, heterogeneity = 0.5,
                     forms = c("linear", "nonlinear")),
  trim_band   = c(0.05, 0.95),
  negative_controls = list(nc_visit = "health_seeking_behavior"),
  nc_criteria       = list(null_band = c(-0.02, 0.02), min_per_domain = 1),
  restrictions      = list(no_transfer = ~ !transfer),
  K = 5, reps = 200, max_reps = 1000, seed = 20261005)

lock    <- create_analysis_lock(design_data, treatment = "A", covariates = W,
                                plan = plan, id = "id")
design  <- assess_design(lock)
sim     <- simulate_design(lock, design)
nc      <- negative_control_ladder(lock, design, sim)
dossier <- design_report(lock, design, sim, nc, file = "dossier.html")
ub      <- unblind(lock, dossier, outcomes = outcome_data,
                   approved_by = "Review team")
fit     <- estimate_effect(ub, method = "tmle")   # or "weighting", "matching"
export_design_log(ub, fit, file = "design_log.json")
```

Exports (12): `analysis_plan`, `create_analysis_lock`, `assess_design`, `simulate_design`, `negative_control_ladder`, `design_report`, `unblind`, `estimate_effect`, `export_design_log`, `save_lock`, `load_lock`, `verify_lock`. S3 methods: `print`, `summary`, `plot`, `as.data.frame`, `tidy`. One example dataset, shipped as separate design and outcome data frames, replaces `sim_func1()`.

A library is a character vector of learner names or the string `"default"`, which expands to the default library of Section 4; the expansion is stored in the plan, so the hash covers it. `tolerance$bias` is absolute bias on the risk-difference scale. `analysis_plan()` validates the plan: estimands from {ATE, trimmed_ATE, ATT, ATO}; ATT and ATO rejected for a time-to-event outcome; `trim_band` required when `trimmed_ATE` is declared; `select` optional (a function of the metrics table, replacing the default rule); `hazards` required for a time-to-event outcome (the hazard-model specification passed to `concrete`); `max_reps` at least `reps`. Every declaration lives in the plan; nothing is declared after the lock is created.

## 4. The fitter: `fit_candidate()`

One internal function serves the simulation (on W, A\*, Y\*) and stage 4 (on the real data, with the candidate the dossier recorded). It has two layers.

**`fit_nuisance(W, A, Y, ps_library, q_library, folds)`** returns cross-fitted g(W), Q(1,W) and Q(0,W), and the cross-validated risk of every learner setting.

- K outer folds; within each training set, a Super Learner with V = 5 inner folds. With K = 1, one Super Learner fit on all rows with V = 5, and predictions from that fit.
- The propensity library is `ps_library` for every candidate. Candidates vary only the outcome library and the truncation.
- Folds are seeded from the plan; every setting uses the same folds.

**`target(nuisance, estimand, truncation)`** is cheap, so one nuisance fit serves every estimand and truncation level.

| Estimand | Targeting |
|---|---|
| ATE, ATT | `tmle::tmle(Y, A, W, Q = cbind(Q0W, Q1W), g1W = g, gbound = c(t, 1 - t), family = "binomial")`. Verified: supplied nuisances are accepted and the bound reaches both the ATE and the ATT. |
| Trimmed ATE | The same call on rows whose cross-fitted g lies inside `trim_band`, with the full-sample nuisance fits. No propensity refit. |
| ATO | Internal TMLE. Fluctuate logit Q along the covariate H = A(1 − g) − (1 − A)g; then ψ = Σ h(Q₁\* − Q₀\*) / Σ h with h = g(1 − g); SE from the influence function. Truncation has no effect, so ATO candidates collapse over truncation. |

Every estimate goes through the implausibility guard carried over from 0.3.0.

**Learners.** The package ships its own xgboost learner, because `SL.xgboost` leaves `tree_method` unset (exact split search; in a probe at n = 2000 on a busy machine, one 500-tree fit took 90 s through `SL.xgboost` and under 1 s with `hist`) and fits a fixed number of trees. The learner uses `tree_method = "hist"`, `nthread = 1`, `min_child_weight = 0`, depths 1 to 5, learning rates 0.1 and 0.3, and the best round within a 500-tree cap chosen on the inner folds; each depth and learning rate enters the library as its own setting. The default library is one learner type per family: elastic net (`glmnet`), MARS (`earth`, degree 2), that xgboost grid, and a small neural net (`nnet`). Every fit stores per-setting and per-round risks; the edge check reads them and reports any tuned hyperparameter whose best value sits on a grid edge (depth 1 is a hard limit and exempt).

## 5. Design stage

**`assess_design(lock)`** cross-fits g with `ps_library`, grades overlap, reports per-estimand weights and effective sample size, checks balance with cobalt, and reports the edge check. It reads only the design data.

**`simulate_design(lock, design)`** runs one plasmode loop that answers which estimands the data can deliver and which candidate to use for each. One repetition, for each surface s:

1. Resample the rows of W with replacement; draw A\* ~ Bernoulli(ĝ(W)), with ĝ from `design`.
2. Draw Y\* ~ Bernoulli(Q_s(A\*, W)).
3. Fit the nuisances once per repetition for g and once per surface and outcome library for Q, then target every (estimand, truncation) pair.
4. Record bias, interval coverage and squared error against the true values.

The true values are computed exactly from Q_s and ĝ over the design sample's W, the finite population being resampled, so they are fixed across repetitions: ATE is the mean of Q_s(1,W) − Q_s(0,W); ATT weights it by ĝ; ATO by ĝ(1 − ĝ); trimmed ATE averages over rows with ĝ inside `trim_band`.

The surface family is Q_s(a,W) = expit(β₀ + γ·m(W) + a·(τ + δ·h(ĝ(W)))). m(W) is a prognostic index, a fixed mix of logit ĝ(W) and a seeded random direction in the standardized covariates, either linear or nonlinear (squares and one interaction). τ is `log_or`; δ is `heterogeneity`, which makes the effect vary with the propensity score, the variation that separates the ATE, ATT and ATO; β₀ is calibrated to `baseline_risk`. The default grid is {linear, nonlinear} × {δ = 0, δ = heterogeneity}, four surfaces. Users can add surfaces as `function(a, W)` returning risks, or supply `q0`, which replaces m(W).

Reading the results:

- **Feasible:** at least one candidate meets the bias and coverage tolerances on every surface, judged on the point estimates. The tolerances are the declared margin; no second margin is applied.
- **Selected:** among candidates for a feasible estimand, the smallest worst-surface RMSE, unless the plan supplies `select`.
- **Monte Carlo uncertainty:** every metric carries its Monte Carlo SE, and coverage a Wilson 95% interval. A cell (estimand, candidate, surface) is unresolved when the 95% interval for its bias or its coverage contains the tolerance. Unresolved cells that can change the decision get further repetitions, in batches, up to `max_reps`. For each estimand at or above the primary on the ladder, these are the unresolved cells of the selected candidate (of every candidate that passes everywhere when the plan supplies its own selection rule) and of any candidate whose failing cells are all unresolved; a candidate with a clear failure cannot become feasible and is not extended; a cell still unresolved at the cap is decided on its point estimate and flagged in the dossier.
- **Failures:** a fit that errors is recorded as failed; a candidate with more than 5% failed fits on any surface does not count toward feasibility.
- **Runtime:** a runtime estimate prints after the first repetition. Repetitions run in parallel through `future.apply` when it is installed and a plan is set.
- **Scope:** the dossier states that feasibility is certified only over the declared family of surfaces.

For a time-to-event outcome, the loop scores risk by `target_time` as a binary outcome; it checks support and selects the truncation only. The dossier states that the hazard models were not stress-tested.

**`negative_control_ladder(lock, design, simulation)`** runs `fit_candidate()` (for each estimand, the candidate the simulation selected for it, or, for an estimand with no feasible candidate, the candidate with the smallest worst-case RMSE, labelled not feasible; the design's folds) for each negative-control outcome, for every declared estimand, on each rung of `restrictions`, starting with the full cohort, and grades the result against `nc_criteria`: per rung, estimand and domain, pass, fail or insufficient; the verdict for a rung and estimand is STOP when any domain fails, FLAG when any is insufficient, otherwise GO. The verdict that gates unblinding is the full cohort's for the primary estimand the dossier selects, because a negative control read on an estimand the design cannot deliver mixes extrapolation error with confounding, so it cannot isolate confounding. (Changed 2026-10-07, approved by Andrew; previously the ATE only.) (Changed 2026-10-07, approved by Andrew: the controls use the analysis's selected candidate rather than a fixed main-terms GLM, so they test the adjustment the analysis will use; `design_report()` refuses a ladder not run on the same simulation.) The default grading rule is "interval": a control reads inside when its 95% CI lies inside `null_band`, outside when the CI lies entirely outside it, and inconclusive otherwise; a domain fails if any control is outside, and a rung and estimand is STOP if any domain fails, FLAG if any is inconclusive or insufficient, otherwise GO. FLAG does not block unblinding. The "point" and "ci" rules remain available. (Added 2026-10-07, approved by Andrew: a point-estimate band narrower than the sampling error fails a control with no effect most of the time.)

## 6. Integrity: lock, dossier, unblinding

**Lock.** `create_analysis_lock()` raises an error if `design_data` contains any of the plan's outcome columns; negative-control outcomes are allowed. It stores the design data, plan, seed and package version. `lock_hash` is SHA-256 over: the plan (function-valued entries deparsed to text), a content digest of every design-data column, the treatment and covariate names, the seed, K, and the package version. Nothing is written back into the lock after creation. `verify_lock()` recomputes the hash; `save_lock()` and `load_lock()` verify on the way out and in.

**Stamps.** `assess_design()`, `simulate_design()` and `negative_control_ladder()` return objects stamped with `lock_hash` and their own content hash.

**Dossier.** `design_report()` checks every stamp against the lock, then walks the ladder: the primary is the first estimand in the declared order that is feasible, and each feasible estimand gets its selected candidate; the dossier flags a decision that rests on cells unresolved at `max_reps`. It attaches the negative-control verdict, strips individual-level vectors, and computes `dossier_hash` over the lock hash, the decision and the component hashes. `file =` renders a Quarto HTML or Word file.

**Unblinding.** `unblind(lock, dossier, outcomes, approved_by, override = NULL)`:

- recomputes the lock and dossier hashes and checks that the dossier belongs to this lock;
- requires `outcomes` to carry the `id` column and the plan's outcome columns; ids not in the design are dropped and logged;
- refuses when no estimand is feasible or the negative-control verdict is STOP, unless `override` gives a written reason, which is recorded;
- returns an `unblinded_lock` holding the lock, dossier, outcomes and approval record (approver, time). The original lock is unchanged.

**Estimation.** `estimate_effect(ub, method = "tmle")` reads the estimand and candidate from the dossier. An explicit `estimand =` is allowed and labeled, in the result and the log, as not the prespecified primary.

**Design log.** `export_design_log()` assembles JSON at export time from the stamps on the objects it receives: plan, hashes, design summaries, decision, approval, overrides, estimates. There is no mutable log.

**Guarantee, stated plainly.** The outcome never enters the lock or a design object (structural, tested), and any later change to the plan, design data or decision is detectable through the hashes. Nothing in R prevents an analyst from reading their own outcome file, so the package and the paper describe the design as tamper-evident, not tamper-proof.

## 7. Estimation backends

All methods return one class, `cr_estimate`: estimand, method, candidate, estimate, SE, CI, n, the size of the target population, the arm risks, and the implausibility guard. `summary()` adds an E-value from `EValue::evalues.RR` on the ratio of the arm risks; with the threat families dropped, this is where the unmeasured-confounding tipping point lives.

| Method | Estimands | Implementation |
|---|---|---|
| `"tmle"` (default) | all four | `fit_candidate()` with the dossier's candidate |
| `"weighting"` | ATE, ATT, ATO, trimmed ATE | `WeightIt::weightit()` (trimmed ATE on the band subset), then `lm_weightit(Y ~ A)` for a risk difference with an M-estimation SE |
| `"matching"` | ATT only | `MatchIt::matchit()` nearest neighbour, caliper 0.2 SD of the logit, then a regression with cluster-robust SEs |
| time-to-event (dispatched by the plan) | ATE, trimmed ATE | `concrete::formatArguments()` (treatment model `ps_library`, `MinNuisance` = the candidate's truncation, hazards from the plan), `doConcrete()`, `getOutput(Estimand = "Risk")` at `target_time` |

The comparators are not simulated; the dossier and the result label them as not stress-tested.

## 9. Tests

Written before the code they cover.

1. **Lock:** outcome columns refused; changing any plan field or design column changes the hash; save and load round-trip; `verify_lock()` detects tampering.
2. **Blinding contract:** a recursive walk finds no outcome column or vector in any design object or dossier; `simulate_design()` runs on design data with no outcome columns.
3. **Fitter:** the handoff test (`estimate_effect()` passes exactly the dossier's library, truncation and fold seed to `fit_candidate()`); truncation changes the ATE and ATT; the ATO TMLE agrees with the augmented ATO estimator and recovers a known truth; the exact true values match a large Monte Carlo draw.
4. **Simulation:** good overlap gives a feasible ATE; severe positivity gives an infeasible ATE and a feasible ATO; the unresolved flag, the targeted extension and its cap, and the failure rule; K is respected.
5. **Dossier and unblinding:** a dossier from another lock is rejected; an edited dossier is rejected; STOP blocks without an override; the override is recorded.
6. **Backends:** weighting matches a direct WeightIt call; matching rejects every estimand but the ATT; a `concrete` smoke test with `skip_if_not_installed()`.
7. **Edge check:** a deliberately narrow grid is flagged.

## 11. 0.4.1 additions

Added 2026-10-06, after a review of what the rebuild dropped and a timing run of a small plan on `cr_example`. Every addition folds into an existing export; the count stays at 12. With the plan's defaults, the existing outputs do not change, except for the new columns and the speed.

Evidence for the additions:

- The rebuild dropped the profile of the patients a trimmed analysis no longer describes, a pre-outcome precision readout, the standard overlap numbers (maximum and 99th-percentile weights, c-statistic), and the Muntner Table S1 export. The estimability paper needs the first three; pharmacoepidemiology readers expect the fourth.
- A small plan (K = 1, GLM only, 50 repetitions, max_reps 200) took 14.6 s for its first repetition and 32 minutes in total. A profile of one repetition put about 70% of the time in `tmle:::oneStepATT`, which `tmle::tmle` runs on every call unless `evalATT = FALSE`, including the calls that target only the ATE or the trimmed ATE.
- On `cr_example` the same run found the ATE feasible and the ATT infeasible, so the example cannot show the ladder moving off the ATE.

### 11.1 Who each estimand describes

`assess_design()` gains two tables, built from the design data only:

- `populations`: one row per design-matrix column. Columns: the full-cohort mean, then for each declared estimand the mean in its target population and the standardized shift from the full cohort (difference over the full-cohort SD). Target populations: ATE, all rows unweighted; trimmed ATE, rows whose cross-fitted g lies inside `trim_band`, unweighted (the population that estimation trims to); ATT, the treated rows; ATO, all rows weighted by g(1 − g).
- `trimmed_profile`, when `trim_band` is set: the number of rows removed, overall and by arm, and for each column the means among removed and kept rows and their standardized difference (difference over the full-cohort SD). Computed directly, not through cobalt.

The dossier gains a section, "Who each estimand describes", that shows both tables. They hold summaries only, so no individual-level values enter the dossier.

### 11.2 Pre-outcome precision

- `simulate_design()` metrics gain three columns per cell: `se_mean` (mean of the reported SE over usable repetitions), `emp_se` (SD of the estimates) and `ci_halfwidth` (mean of half the interval width).
- The verdict gains `ci_halfwidth`, the selected candidate's largest half-width over the surfaces.
- `expected_events`: for each estimand, surface and arm, the expected number of events among the rows the estimator uses, computed from the surface risks and the observed treatment: for the treated arm, the sum of q_s(1, W) over the treated rows; for the control arm, the sum of q_s(0, W) over the control rows. The rows are all design rows for the ATE, ATT and ATO, and the rows inside `trim_band` for the trimmed ATE. The dossier reports the range over surfaces. It never reads the outcome.
- `tolerance$ci_halfwidth` is optional. When declared, a cell passes only if it also meets this tolerance, so feasible also means informative. It does not enter the unresolved-cell rule, and the dossier says so.

### 11.3 Surface grid

- `surfaces$log_or` and `surfaces$heterogeneity` accept vectors. A new `surfaces$prognostic` (default 1) scales the prognostic index: Q_s(a,W) = expit(β₀ + γ·m(W) + a·(τ + δ·h(ĝ(W)))), with γ from `prognostic`.
- The grid is forms × prognostic × log_or × {0, heterogeneity values}. Surface names list every value, for example "linear, prognostic 1, log OR 0.5, heterogeneity 0". With the defaults the grid is the same four surfaces, with the longer names.
- A steward `q0` replaces the forms and is still scaled by `prognostic`.
- `analysis_plan()` messages when the grid exceeds 12 surfaces: runtime grows with the grid, and requiring every surface makes feasibility stricter.

### 11.4 Overlap numbers and the record

- The `ess` table gains `max_weight` and `p99_weight` per estimand, from `.estimand_weights()` on the cross-fitted g. `overlap` gains `c_statistic`, the area under the ROC curve of the cross-fitted g for A, by the rank formula.
- `plot(design)` draws the distribution of the cross-fitted g by arm.
- The dossier gains a section, "Prespecified plan", that shows the ladder order, tolerances, trim band, propensity library, candidates with their library expansions and truncations, the surface grid, K, V, reps, max_reps, seed, negative controls, criteria, restrictions and roles.
- `analysis_plan()` gains an optional `roles`, a named list of character values (for example `analyst`, `data_steward`, `reviewers`), stored in the plan and so covered by the lock hash.
- `create_analysis_lock()` records `created` (the creation time, UTC). It is not part of `lock_hash`, so the hash stays reproducible from its inputs. The dossier copies it, and `dossier_hash` covers it.
- `export_design_log(x, fit, file, format = c("json", "muntner"))`. `"muntner"` returns, and writes as CSV when `file` is given, the Table S1 columns of Muntner et al. (2024): `date`, `stage`, `issue`, `decision`, `rationale`, `decided_by`, the same columns as the 0.3.0 export. Rows: the lock (created; plan declared), the design assessment (overlap grade), the simulation (each estimand's status and selected candidate), the negative-control verdict, the dossier decision (primary estimand), any override (its written reason), the approval (approver and time), and each estimate (estimand, method; marked when not the prespecified primary). `decided_by` comes from `roles` where one applies and is NA otherwise.

### 11.5 Speed

- `.target_tmle()` passes `evalATT = FALSE` to `tmle::tmle` on every call that does not read the ATT, guarded by a check that the argument exists, as `prescreenW.g` is guarded now.
- The extension batches are unchanged.

### 11.6 Example data that shows the ladder

- `data-raw/make_cr_example.R` is regenerated with stronger treatment assignment on severity and an effect that varies with severity, so that the ATE is infeasible and a lower rung of the ladder is feasible under both the default plan and the small plan the vignette uses. (Amended 2026-10-07, approved by Andrew: the implemented cohort, assign 3.0 and modifier 0.3, gives the trimmed ATE and the ATO under the small plan, and the ATO only under the default plan with 50 repetitions.)
- The help page gives the true value of each estimand for the cohort, computed from the generating model over the cohort's covariates, so the vignette can compare estimate and truth.
- Before the data are committed, a run of both plans confirms the ladder moves. If no setting gives that result in both plans, the data change stops and the finding is reported.

### 11.7 Tests

Written before the code they cover.

1. `populations`: on a fixture with a known covariate shift, the ATT and ATO means and shifts match a hand calculation; the ATE column equals the full-cohort mean.
2. `trimmed_profile`: on a fixture with known out-of-band rows, the counts by arm and the standardized differences match.
3. Precision: `se_mean`, `emp_se` and `ci_halfwidth` match hand calculations on a fixed results table; a declared `ci_halfwidth` tolerance turns a passing cell into a failing one; expected events match a hand calculation for each arm and estimand.
4. Grid: vectors give the declared number of surfaces with the declared names; the defaults give four surfaces and the same metrics as before, apart from names and the new columns.
5. Overlap: `c_statistic` matches a hand calculation; `max_weight` and `p99_weight` match `.estimand_weights()`.
6. Record: the Muntner CSV has the six columns and the rows listed in 11.4; editing `created` in a dossier is detected; `roles` changes the lock hash.
7. Speed: ATE and trimmed-ATE estimates and SEs are identical with `evalATT` TRUE and FALSE.
8. Example data: under the vignette's small plan, the ATE is infeasible and at least one lower rung is feasible.

### 11.8 Scope notes

- Missing outcomes stay complete case. The Rescue.Co protocol declared IPCW as primary; the new paper states the change and reports the IPCW result as a sensitivity analysis from the Rescue.Co scripts.
- Still out: the data-quality threat families, alternative selection rules, variance-method selection, the collider check, and the 0.3.0 survival estimators. The new paper must not claim them, nor the 0.3.0 surface (sixteen verbs, outcome store, masking), the STOP result under unmeasured confounding, or tamper-proof blinding.
